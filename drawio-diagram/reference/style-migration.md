# 图表风格迁移

用户给了参考图，要按它的版式和配色重画一张图。内容来自当前模型代码或用户描述；参考图只提供风格。

## 使用时机

- 「按这个风格画」「照这个配色/排版」
- 参考图是论文图、截图或手稿，新图的内容是另一个模型或另一段代码

只有参考图、没有内容时，先问新图要画什么，不要把参考图里的模块名照抄下来。

## 工作流程

### 1. 先写成风格卡片，再画

对照参考图写明这些项，写不出的标「看不清」，不要用默认样式填：

| 项 | 记录 |
|----|------|
| 画布 | 背景色、是否网格、留白多少 |
| 方向 | 自下而上、自上而下、从左到右、左右分栏 |
| 节点 | 形状、圆角、描边宽度、填充、字体、字号、是否加粗 |
| 分组 | 有没有容器，标题在容器内的哪一边 |
| 连线 | 正交 / 直线 / 曲线，箭头形状，虚线表示什么 |
| 标注 | 维度写在节点里还是连线上，图题在上还是在下 |
| 重复结构 | 用 `× N` 还是真的铺开 |

### 2. 内容另取，不从参考图抄

- 模型结构：信息取舍按 [tech-diagram.md](tech-diagram.md)（画什么、不编维度），外观按风格卡片。
- 仓库里的技术栈、分层、表结构、E-R：信息按 `codegen-diagram` 的对应 reference，外观按风格卡片。
- 调用顺序：信息按 [uml-diagram.md](uml-diagram.md)。
- 参考图里的模块名、通道数、论文标题、作者名一律不搬。对不上的结构标成假设。

### 3. 冲突时谁优先

- 颜色、形状、方向、字号：参考图优先。
- XML 必须能打开：转义、唯一 id、标签闭合不受参考图影响。参考图是 PNG 时，里面的文字样式不能违反 XML 规则。
- 参考图很挤或字号小于 12px：保持它的配色和方向，但把字号提高到仍能看清的下限，并在说明里写一句改了什么。

## 输出

风格卡片、内容来源（代码路径或用户描述）、完整 XML、图题。说明里明确「风格来自参考图，名称来自……」。
