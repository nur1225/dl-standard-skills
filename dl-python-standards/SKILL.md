# Python 深度学习算法代码与注释规范

## 编写与重构

- 按 PEP 8 命名。保留 `q`、`k`、`v`、`iou` 等领域惯例，中间结果用 `attn_weights`、`enc_feat_s4` 等能体现含义的名称。按算法职责组织子模块。
- 为函数与方法的业务参数和返回值添加与项目 Python 版本兼容的类型注解，覆盖 `__init__` 和 `forward`。模型类和核心算法函数使用 Google 风格 docstring。在类中说明职责与构造参数，在实际接收或返回张量的方法中用 `Args`、`Returns` 写明形状与语义。
- 将可调阈值、归一化参数、下采样倍率和稳定项 `eps` 放入有语义的参数、具名常量或现有配置。轴索引和由定义决定的数可就地写明，例如 Q、K、V 合计三个投影。
- 重构前对照调用方确认输入输出、训练梯度和已保存权重依赖的参数名。按本次修改涉及的行为选择验证方式。

## 张量与注释

- 在接口处定义符号和数据约定。图像写明布局、RGB/BGR、dtype 和像素范围。框坐标写明格式及单位。掩码写明形状、广播轴和布尔极性。只记录该接口实际使用的约定。
- 在 `view`、`reshape`、`permute`、`transpose`、`einsum`、`cat`、`stack`、跳跃连接和多尺度融合处，就近标明输入、中间和输出形状。连续的变换可合用一条注释。例如 `features.flatten(2).transpose(1, 2)` 对应 `[B, C, H, W] → [B, C, H*W] → [B, H*W, C]`。改动轴顺序时同步更新注释。
- 注释解释会改变算法结果的选择，例如插值对齐方式、锚框匹配条件、损失归约的分母。删除仅复述卷积、激活、赋值等 API 行为的注释。

## 设备、精度与边界

- 新建张量时从输入或模块取得 device，按用途选择 dtype。布尔掩码、整型索引和浮点特征各自保留所需类型。需要随模型迁移的持久张量可注册为 buffer。
- 对除法、`log`、`sqrt` 和 softmax，明确合法输入域以及空集合、零分母的预期行为。依据公式选择处理方式。使用 `eps` 时确认它在实际计算 dtype 中可表示，且不会改变有效输入的含义。
- AMP 下检查第一个可能溢出的算子。点积已溢出时，仅将后续 softmax 转为 FP32 无法恢复分数。处理注意力时核对所用 API 的 mask 极性，并定义整行无有效键的输出。填充值本身不能决定空行语义。

## 按任务查阅

- 多头注意力、布尔掩码或整行屏蔽时的前向与梯度行为，参见 [PyTorch 注意力示例](references/attention.md)。
- 损失函数的数值域与归约，以及 NumPy/OpenCV 的通道、缩放和框坐标，参见 [损失与前后处理](references/loss-and-preprocess.md)。
- 数据加载、分布式训练、梯度累积、AMP、验证循环或指标统计，参见 [训练与推理工程规范](references/training-inference.md)。
- ONNX 导出、算子与 opset 兼容性、TensorRT 构建、动态形状或跨后端精度验收，参见 [模型导出与部署规范](references/export-deployment.md)。

## 审查与验证

- 审查请求先给出影响结果的问题，指出位置、触发输入和可观察后果，再报告类型与注释问题。区分已复现的问题和需要特定设备或数据才能确认的判断。
- 选择能暴露本次错误的小输入。例如用非方形图像或长宽不同的特征图检查 H/W 对调，用一个已知像素检查 RGB/BGR 与归一化，用只有一个有效键的查询检查 mask 极性。涉及训练或混合精度时，按需检查实际 dtype 下的输出、梯度有限性及与参考结果的误差。
